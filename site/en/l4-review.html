Summary and quiz

Key ideas of the lecture

  • On a GPU the silicon goes to arithmetic units instead of control and caches; GPUs are throughput-oriented, CPUs latency-oriented.
  • CUDA = SIMT: same instruction, many threads. Divergence (different paths within a warp) slows down.
  • The host prepares the work (allocate, copy, launch), the device executes. Flow: profile → find the parallel part → copy → compute → copy back → verify (FP is not associative) → iterate.
  • Hierarchy: grid → block (≤ 1024 threads, on one SM) → warp (32 consecutive threads) → thread. Linear index: tz·bx·by + ty·bx + tx, warp = index/32.
  • Blocks are independent and unordered → scalability. Cooperation within a block: shared memory + __syncthreads().
  • Memory: local per thread, shared per block, global for everyone; read-only constant and texture.

Common mistakes

  • Mixing up blockDim (threads per block) and gridDim (blocks per grid).
  • Thinking a warp can span two blocks: warps are always inside one block; a 48-thread block = 2 warps (the second half full).
  • Assuming block 0 runs before block 1.
  • Expecting CPU and GPU results to match bit for bit (different summation order).

Open-ended questions for the final

1. A kernel uses 100-thread blocks. How many warps per block, and how many thread slots are wasted?

⌈100/32⌉ = 4 warps; 4·32 = 128 slots, 28 empty (only 4 threads active in the last warp). Choosing block sizes that are multiples of 32 avoids this waste.

2. if (threadIdx.x < 48) A(); else B(); in a 128-thread block: how many warps diverge?

Warp 0 (0–31): all A, no divergence. Warp 1 (32–63): 32–47 A, 48–63 B → diverges. Warps 2, 3: all B. So only 1 warp.

3. Why must blocks be independent? What would we lose if they were not?

So that the runtime can distribute blocks to any SM in any order. If blocks waited for each other (order assumptions, synchronisation across blocks), the same program might not run, or might deadlock, on GPUs with different numbers of SMs: scalability would be lost.

  4. 8

What lets CUDA programs run unchanged on GPUs with different numbers of SMs?

  1. The warp size being 32 on every GPU.
  2. Thread blocks being independent and runnable in any order.
  3. __syncthreads() synchronising all blocks.
  4. The programmer assigning blocks to SMs by hand.

GPU results do not match CPU results bit for bit. The most likely reason?

  1. The GPU does not support floats.
  2. FP addition is not commutative.
  3. __syncthreads() is always missing.
  4. FP operations are not associative; parallel code performs operations in a different order.
