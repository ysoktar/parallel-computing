Summary and quiz

Key ideas of the lecture

  • Kernel = the body of the loop; the outer loops become threads. Host: cudaMalloc → cudaMemcpy (H→D) → kernel<<<grid, block>>> → cudaMemcpy (D→H) → cudaFree.
  • Global index = blockIdx·blockDim + threadIdx (on each axis); row-major address row·width + col; round the grid up, check the bounds.
  • __syncthreads(): barrier within a block, everyone in the block must execute it.
  • Blocks are assigned to SMs block by block; warp = 32 threads, the scheduling unit; many warps = latency hiding.
  • Naive matmul has CGMA = 1 → bandwidth-bound (~6% efficiency). Tiling: load a tile into shared memory once, use it T times → T times less global traffic, CGMA = T.
  • Two barriers in the tiled kernel: after loading (tile filled) and after computing (not overwritten).

Common mistakes

  • Passing a number of elements to cudaMalloc/cudaMemcpy: sizes are always in bytes (n * sizeof(float)).
  • Using x for the row and y for the column: consecutive threads go to distant elements (coalescing breaks) and the matrix is computed transposed.
  • Forgetting the second __syncthreads() in the tiled kernel: a fast thread writes the next phase's tile while others are reading.
  • Timing right after the kernel: the launch is asynchronous, call cudaDeviceSynchronize() first.

Open-ended questions for the final

1. Write a kernel that multiplies an n-element array by s, and the host code that launches it (256 threads per block, n may not be a multiple of 256).

__global__ void scale(float* a, float s, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) a[i] *= s;              // the extra threads do nothing
}
// host:
float* d;
cudaMalloc((void**)&d, n * sizeof(float));
cudaMemcpy(d, h, n * sizeof(float), cudaMemcpyHostToDevice);
scale<<<(n + 255) / 256, 256>>>(d, 2.0f, n);
cudaMemcpy(h, d, n * sizeof(float), cudaMemcpyDeviceToHost);
cudaFree(d);

2. What is the CGMA ratio of tiled matmul with TILE_WIDTH = T? Show it.

In each phase a thread does 2 global reads (one element each into Mds and Nds) and, in the inner loop, T multiplications + T additions = 2T FP operations. CGMA = 2T / 2 = T. With T = 16, a 16 times improvement: on the G80 the 21.6 GFLOPS bound rises to ~345 GFLOPS (close to the 367 peak).

3. Compute the shared memory use of 16×16 tiled matmul and how many blocks fit on a G80 SM. What is the limit?

Mds + Nds = 2·16·16·4 B = 2 KB/block; 16 KB/SM → 8 blocks by shared memory. But with 256 threads/block, 768/256 = 3 blocks. The limit: threads per SM (not shared memory).

Check yourself

Why is &Md passed in cudaMalloc((void**)&Md, size)?

  1. Because Md will be allocated in host memory.
  2. To give the size in bytes.
  3. So that the function can write the allocated address into the variable Md.
  4. To copy data into Md.

With 256-thread blocks and 3 blocks on an SM, how many warps are on the SM?

  1. 8
  2. 24
  3. 768
  4. 32

Why is the CGMA ratio of naive matmul 1?

  1. There is one FP operation per shared memory access.
  2. Each thread reads one element.
  3. Each thread uses one register.
  4. Each iteration does 2 global reads and 2 FP operations (multiply, add).

What can happen if the second __syncthreads() in the tiled kernel is removed?

  1. A thread may load the next phase's tile while another thread is still reading the previous phase's values.
  2. A compile error.
  3. The write to Pd is no longer coalesced.
  4. Nothing; the second barrier is unnecessary.

Which is true for __constant__ variables?

  1. They live in a separate on-chip memory, no cache needed.
  2. They are declared inside the kernel.
  3. All grids see the same version; stored in global memory but cached.
  4. Kernels can write to them.
