Summary and quiz

Key ideas of the lecture

  • Moore's law is about the number of transistors, not frequency. Frequency stopped at 2–4 GHz around 2005 because of power and heat (power ∝ f³); the extra transistors went into cores.
  • Getting performance from many cores needs parallel software; that is what this course is about.
  • Flynn: SISD, SIMD, MISD, MIMD. Multi-core CPUs and GPUs are MIMD; the GPU's programming model is SIMT.
  • Shared memory (common address space, easy, limited scale; NUMA) ↔ distributed memory (message passing, harder, scales far).
  • CPUs are designed for latency (big caches, complex control), GPUs for throughput (many simple ALUs, wide memory buses).
  • speedup = tseq/tpar, efficiency = speedup/N. Amdahl: 1/((1−α) + α/N), ceiling 1/(1−α). Gustafson: (1−α) + αN.

Common mistakes

  • Taking α to be the serial part. In this course α is the parallelisable part; the serial part is 1 − α.
  • Mixing up speedup and efficiency: a speedup of 8 on 16 cores is 50% efficiency; there is no such thing as "8 times efficiency".
  • Thinking NUMA is distributed memory: in NUMA addressing is shared, remote memory is just slower.
  • Comparing against a slow sequential version: the golden rule compares with the fastest known sequential solution.

Open-ended questions for the final

1. 95% of a program can be parallelised. What are the speedup and efficiency on 19 cores? What is the most you can get with infinitely many cores?

1/(0.05 + 0.95/19) = 1/(0.05 + 0.05) = 10; efficiency 10/19 ≈ 53%. Bound: 1/0.05 = 20.

2. For the same program, what are the speedup and efficiency on 19 cores according to Gustafson? Why is it different from Amdahl?

0.05 + 19·0.95 = 0.05 + 18.05 = 18.1; efficiency 0.05/19 + 0.95 ≈ 95.3%. Gustafson assumes the problem grows with the number of cores (fixed time); Amdahl keeps the problem fixed.

3. Why was it not possible to keep raising the clock frequency? Give two reasons.

(1) Power grows very fast with frequency (about f³): the heat cannot be removed. (2) A high-frequency clock signal is hard to generate and distribute across the chip (the waveform degrades). Lowering the voltage helped for a while but was not enough.

4. 10,000 nodes in a server farm will work together. Shared or distributed memory? Why?

Distributed memory: shared memory becomes a bottleneck in a single common medium (memory bus, cache coherence) and chokes at tens to hundreds of cores. In distributed memory each node has its own memory and communicates by messages; that is expensive, but with no shared bottleneck it scales very far.
