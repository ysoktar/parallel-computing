Summary and quiz

Summary

  • nvcc: .cu → PTX (virtual ISA) → ptxas → SASS (cubin). A cubin for X.y runs only on X.z (z ≥ y); future GPUs need PTX + JIT. -arch selects the PTX, -code the binary.
  • Kernel launches are asynchronous: call cudaDeviceSynchronize() when timing; the first call includes initialisation.
  • Register and shared memory limits decide the threads/blocks per SM; too many registers → spill → local memory (as slow as global).
  • Global: coalescing (aligned 32/64/128 B segments), pitch in 2D. Local: variable-indexed arrays and spills.
  • Shared: 32 banks, bank = word index % 32; different words in the same bank = conflict; for s[stride·tid] the degree is gcd(stride, 32); [32][33] padding for column reads.
  • Constant: best when everyone reads the same address (broadcast). Texture: 2D locality, interpolation, boundary handling; read-only, needs a CUDA array.

Common mistakes

  • Mixing up coalescing and bank conflicts: coalescing is about consecutive addresses in global memory; bank conflicts are about different words falling into the same bank of shared memory. s[2*tid] means half efficiency in global memory and a 2-way conflict in shared memory.
  • Taking the pitch for a number of elements: the pitch is in bytes, the row start is (char*)p + r*pitch.
  • Having consecutive threads read consecutive addresses of constant memory: that is the bad pattern for constant memory (32 separate requests).
  • Thinking a binary built with -code=sm_70 runs on an 8.x GPU (not across a major change, and with no PTX there is no JIT).

Open-ended questions for the final

1. 32 threads read s[8*threadIdx.x + 1] from __shared__ float s[1024]. How many ways is the bank conflict?

Bank = (8i + 1) % 32: 1, 9, 17, 25, 1, 9, … → only 4 banks are used, with 8 different words each → 8-way (gcd(8, 32) = 8; the offset does not change the degree).

2. Why is tile[32][33] used instead of __shared__ float tile[32][32] in the transpose? Show it with the bank calculation.

With width 32 the bank of tile[r][c] is (32r + c) % 32 = c: the 32 elements of a column are in the same bank, so a warp reading a column makes a 32-way conflict. With width 33 the bank is (33r + c) % 32 = (r + c) % 32: 32 different banks for r = 0..31 → no conflict. The cost is 32 floats.

3. A kernel uses 40 registers per thread and an SM has 65,536 registers. With 256 threads per block, how many blocks fit on an SM at most (by registers)?

256·40 = 10,240 registers per block; 65,536 / 10,240 = 6.4 → 6 blocks (1536 threads). Bringing it down to 32 registers allows 8 blocks (2048 threads): register usage directly decides occupancy.

4. When do you choose constant memory and when texture memory? One example each.

Constant: when all threads read the same small data at the same time, e.g. the coefficients of a convolution filter (every thread reads the same coefficient at the same moment → broadcast). Texture: reads that are local in 2D but irregular, and fractional coordinates, e.g. image rotation (texRotate.cu): neighbouring pixels come from the cache, bilinear interpolation and edge handling are done in hardware.

Check yourself

Can a compute capability 8.6 GPU run an application compiled only with -gencode arch=compute_70,code=sm_70?

  1. Yes, the sm_70 binary runs on 8.6.
  2. No: binaries are not compatible across major versions and no PTX is embedded.
  3. Yes, the driver JIT-recompiles the sm_70 binary.
  4. Only if compiled with the same driver version.

Why is cudaDeviceSynchronize() needed when timing a kernel?

  1. To complete memory allocation.
  2. Because cudaMemcpy is asynchronous.
  3. To synchronise the blocks with each other.
  4. Kernel launches are asynchronous; timing without waiting for completion gives a far too short (wrong) time.

Which variable is most likely to be placed in local memory?

  1. An automatic array accessed with an index computed at run time.
  2. An int loop counter.
  3. A __shared__ array.
  4. A __constant__ array.

Rows of 700 bytes were allocated with cudaMallocPitch (256 B alignment). How do you reach the start of row r?

  1. (float*)((char*)p + r * 700)
  2. p + r * pitch
  3. (float*)((char*)p + r * pitch), pitch = 768
  4. (float*)((char*)p + r * 512)
