How the topics connect

  1. Why parallel? (L1) Frequency scaling hit the power wall; performance now comes from many cores and GPUs. Amdahl's and Gustafson's laws describe the limits of the gain.
  2. How to design? (L2) PCAM: partition the problem, identify communication, agglomerate the pieces, map them to processors. Decomposition patterns (geometric, pipeline, …) and program structures (SPMD, master-worker, map-reduce, fork/join).
  3. Shared memory on the CPU (L3) C++11 threads; preventing data races with mutexes, semaphores, atomics and monitors.
  4. Data parallelism on the GPU (L4–L5) One thread per data element: grid → block → thread, indexing with blockIdx/threadIdx, warps, synchronisation within a block, and tiling with shared memory.
  5. Feeding the memory (L6) Arithmetic is cheap, memory is expensive: register/shared limits, coalescing, pitch, constant and texture memory. The transpose example brings all of this together.
