A GPU is a kitchen that takes the order and says "OK" at once. A kernel launch does not make the CPU wait (asynchronous); you learn about an error inside the kernel only later, when you ask "is it done?" (cudaDeviceSynchronize()). The first half of this lecture is catching errors in the right place. The second half is performance: a warp's 32 threads share one program counter, so branches need care; loops get faster with unrolling and the right counter type.

Where and when errors are caught

  • All runtime functions return an error code (cudaError_t).
  • But an asynchronous function returns before the device has finished, so its error code cannot report errors that happen on the device later. It only reports errors on the host before the task starts (typically parameter validation).
  • If an asynchronous error occurs, it is reported by some subsequent, unrelated runtime call. (The error shows up "on the wrong line"!)
  • The only way to check for asynchronous errors right after an asynchronous call is to call cudaDeviceSynchronize() right after it and check its return value.

The error variable: Peek and Get

  • The runtime keeps an error variable per host thread: initially cudaSuccess, overwritten every time an error occurs (a parameter error or an asynchronous error).
  • cudaPeekAtLastError(): returns this variable (does not reset it).
  • cudaGetLastError(): returns the variable and resets it to cudaSuccess.
  • Kernel launches do not return an error code. To get pre-launch errors (such as an invalid configuration), call Peek/Get right after the launch.
  • To make sure the returned error does not come from calls before the launch, the variable must be cudaSuccess right before the launch: e.g. a cudaGetLastError() just before the launch.
  • Since launches are asynchronous, an application that wants to see asynchronous errors must synchronise between the launch and Peek/Get.
cudaGetLastError();                        // make sure the error variable is cudaSuccess before the launch
k<<<(n + 255) / 256, 256>>>(d, n);
cudaError_t l2 = cudaGetLastError();       // launch / configuration errors
cudaError_t r2 = cudaDeviceSynchronize();  // errors during execution

In a program without error checks, even a crashed kernel looks "successful" and the results are garbage; the error is only reported at the next cudaMemcpy, on an unrelated line. What the exam wants: cudaGetLastError() after the launch, then cudaDeviceSynchronize(), checking the return value of both.
