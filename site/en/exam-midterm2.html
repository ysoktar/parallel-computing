Index formulas to memorise

// 2D grid + 2D block: each thread one (row, col) element int col = blockIdx.x * blockDim.x + threadIdx.x; // x → column (consecutive in memory) int row = blockIdx.y * blockDim.y + threadIdx.y; // y → row A[row * width + col] // row-major: row * width + column // linear thread number in the block (this decides the warp: warp = id / 32) 1D: id = threadIdx.x 2D: id = threadIdx.y * blockDim.x + threadIdx.x 3D: id = threadIdx.z * blockDim.x * blockDim.y + threadIdx.y * blockDim.x + threadIdx.x // number of blocks to cover the data (round up) + bounds check dim3 block(16, 16); dim3 grid((width + block.x - 1) / block.x, (height + block.y - 1) / block.y); if (row < height && col < width) { ... }

In dim3(a, b) x comes first, then y. dim3(8, 32): blockDim.x = 8 (8 columns), blockDim.y = 32 (32 rows). The x axis is columns, the y axis rows; warps are formed with threadIdx.x varying fastest.

Problem type 1: Which index points where?

Past exam question: "mapping of tiled matrix multiplication with <<<(3,3),(8,32)>>>". The solution below goes step by step so that it covers every question of this type.

Worked example: <<<dim3(3,3), dim3(8,32)>>>

__global__ void MatMul(const float* M, const float* N, float* P, int K, int Pcols)
{
    int row = blockIdx.y * blockDim.y + threadIdx.y;   // 0..95
    int col = blockIdx.x * blockDim.x + threadIdx.x;   // 0..23
    float sum = 0;
    for (int k = 0; k < K; ++k)
        sum += M[row * K + k] * N[k * Pcols + col];
    P[row * Pcols + col] = sum;
}
// MatMul<<>>(Md, Nd, Pd, K, 24);
  1. How many threads and warps? 8·32 = 256 threads per block (≤ 1024 ✓), 3·3 = 9 blocks → 2304 threads. 256/32 = 8 warps per block → 72 warps in total.
  2. Index ranges: blockIdx.x, blockIdx.y ∈ {0,1,2}, threadIdx.x ∈ 0..7, threadIdx.y ∈ 0..31.
  3. Region of P covered: columns = 3·8 = 24, rows = 3·32 = 96. So it fits exactly if P is 96×24 (M 96×K, N K×24). For a smaller matrix if (row < H && col < W) is required; for a larger one the grid must grow.
  4. A given thread: blockIdx = (2,1), threadIdx = (5,10) → row = 1·32 + 10 = 42, col = 2·8 + 5 = 21. It writes P[42·24 + 21] = P[1029], reading row 42 of M (M[42·K + k]) and column 21 of N (N[k·24 + 21]).
  5. Which block covers which region? Block (bx, by) covers rows 32·by … 32·by+31, columns 8·bx … 8·bx+7. For example (2,1): rows 32–63, columns 16–23.
  6. Warps: the linear id in the block is ty·8 + tx. Warp 0 = ids 0–31 = ty = 0..3 (8 threads each). So one warp is a 4-row × 8-column piece of P. Warp w: ty = 4w … 4w+3.
  7. Coalescing (one load of one warp, for a fixed k):
    • N[k·24 + col]: the 8 threads of a row read 8 consecutive floats (32 B); the 4 rows of the warp read the same addresses → one 32 B segment. Good.
    • M[row·K + k]: the 8 threads of a row read the same address; the 4 rows read 4 different addresses (K floats apart) → 4 segments, 4 bytes used from each. Bad (though caching/broadcast helps).
    • Writing P[row·24 + col]: 4 rows × 8 consecutive floats → 4 separate 32 B segments. Four pieces instead of one 128 B transaction; the slide rule: both the block width and the array width should be multiples of the warp size (32). That is why blockDim.x = 8 is not ideal.

The tiled (shared memory) version with the same configuration

The tiled kernel in the slides assumes a square TILE_WIDTH × TILE_WIDTH block (Mds[ty][tx], Nds[ty][tx], each thread loads one element of each matrix). With 8×32 blocks this does not work directly; the P tile is 32 rows × 8 columns. Choosing a phase width (along k) of TK = 8:

#define BX 8    // blockDim.x  = number of columns of the P tile
#define BY 32   // blockDim.y  = number of rows of the P tile
#define TK 8    // width taken along k in each phase

__global__ void MatMulTiled(const float* M, const float* N, float* P, int K, int Pcols)
{
    __shared__ float Mds[BY][TK];   // 32×8 = 256 elements: every thread loads one
    __shared__ float Nds[TK][BX];   //  8×8 =  64 elements: only threads with ty < 8 load
    int tx = threadIdx.x, ty = threadIdx.y;
    int row = blockIdx.y * BY + ty;
    int col = blockIdx.x * BX + tx;
    float sum = 0;
    for (int m = 0; m < K / TK; ++m) {
        Mds[ty][tx] = M[row * K + (m * TK + tx)];
        if (ty < TK)
            Nds[ty][tx] = N[(m * TK + ty) * Pcols + col];
        __syncthreads();                  // tiles completely filled (OUTSIDE the if!)
        for (int k = 0; k < TK; ++k)
            sum += Mds[ty][k] * Nds[k][tx];
        __syncthreads();                  // nobody overwrites for the next phase before all are done
    }
    P[row * Pcols + col] = sum;
}
  • Shared memory per block: (32·8 + 8·8)·4 B = 1280 B.
  • Global reads: one block reads 32×K elements of M and K×8 of N = 40K; the naive version reads 256 threads × 2K = 512K. Reduction 512/40 = 12.8×. General formula (BX×BY block): 2·BX·BY / (BX + BY); for a square T×T this reduces to T (the slides' "16×16 → 16 times").
  • Alternative: TK = 32 with Mds[32][32] (each thread loads 4 elements) and Nds[32][8] (each thread 1). Fewer phases, more shared memory. Whichever you choose in the exam, write clearly who loads what and the two __syncthreads().

"Which locations does this code touch?" exercises

Answer each one yourself first, then open the solution.

(a) A is 8×8 row-major, k<<<2, 4>>>(A, 8):

__global__ void k(float* A, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 0..7
    A[i * N] = 0;
}

i = 0..7, address 8i: A[0], A[8], …, A[56]. That is column 0. Consecutive threads write addresses 8 floats (32 B) apart → each thread a separate 32 B segment: not coalesced. Writing A[i] would be row 0, and coalesced.

(b) B is 16×16 (width = 16), k2<<<dim3(2,2), dim3(8,8)>>>:

__global__ void k2(int* B, int width) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    B[x * width + y] = threadIdx.x;      // careful: x is used as the row!
}

The whole 16×16 matrix is covered (2·8 = 16 in each direction), but transposed: thread (x, y) writes row x, column y. blockIdx=(1,0), threadIdx=(3,5) → x = 11, y = 5 → writes 3 into B[11·16 + 5] = B[181]. Within a warp threadIdx.x varies consecutively → addresses 16 elements (64 B) apart → not coalesced. Fix: B[y * width + x]. As values, each element gets threadIdx.x = x % 8 of its row; so every element of row r of B becomes r % 8.

(c) In a kernel launched with <<<4, 256>>>, which warp is the thread with blockIdx.x = 2, threadIdx.x = 37 in, what is its global id, and what happens if it reads a[2*i]?

Global id i = 2·256 + 37 = 549. It is in warp 1 of its block (37/32 = 1; warps are numbered within a block, blocks do not share warps). a[2*i]: consecutive threads are 8 B apart → the warp spreads 32 floats over 256 B → 2 lines of 128 B (or 8 segments of 32 B) are moved, half of it used: 50% efficiency.

Problem type 2: Using shared memory

  • __shared__ float s[N]; is declared inside the kernel; one copy per block, all threads of the block see the same one, its lifetime is that of the kernel/block.
  • On-chip, very fast (the fastest after registers); small (16 KB per SM on the G80).
  • Pattern: (1) cooperatively load from global into shared (each thread a few elements), (2) __syncthreads(), (3) read/compute repeatedly from shared, (4) __syncthreads() if needed, (5) write the result to global.
  • Purpose: reduce global memory traffic (raise CGMA) and let threads share data. "Shared memory = user-controlled cache."
  • Another block cannot see a block's shared memory; blocks communicate through global memory.
#define B 256
__global__ void reverseBlock(int* d)
{
    __shared__ int s[B];
    int t = threadIdx.x;
    int base = blockIdx.x * B;
    s[t] = d[base + t];          // 1) load
    __syncthreads();             // 2) has everyone loaded?
    d[base + t] = s[B - 1 - t];  // 3) read what ANOTHER
}                                //    thread loaded
// reverseBlock<<>>(d);

Remove the __syncthreads() above and thread t may read s[B-1-t] before a thread in another warp has written it: a race condition, undefined result. Whenever a thread reads shared data written by another thread, there must be a barrier in between.

"First just copy, without computing." If shared memory also needs data from outside the region you will write (e.g. the border/halo region in a convolution): first write the kernel so that it only does a "global → shared → global" copy and check that the output equals the input. Once the indices are right, add the computation. In the exam, too, check the shared-memory load indices separately.

The whole tiled matrix multiplication, with a phase-by-phase visualisation: L5 page. In short:

__global__ void MatrixMulKernel(float* Md, float* Nd, float* Pd, int width)
{
    __shared__ float Mds[TILE_WIDTH][TILE_WIDTH];
    __shared__ float Nds[TILE_WIDTH][TILE_WIDTH];
    int bx = blockIdx.x, by = blockIdx.y;
    int tx = threadIdx.x, ty = threadIdx.y;
    int Row = by * TILE_WIDTH + ty;
    int Col = bx * TILE_WIDTH + tx;
    float Pvalue = 0;
    for (int m = 0; m < width / TILE_WIDTH; ++m) {
        Mds[ty][tx] = Md[Row * width + (m * TILE_WIDTH + tx)];   // M: row Row, column tx of phase m
        Nds[ty][tx] = Nd[(m * TILE_WIDTH + ty) * width + Col];   // N: row ty of phase m, column Col
        __syncthreads();
        for (int k = 0; k < TILE_WIDTH; ++k)
            Pvalue += Mds[ty][k] * Nds[k][tx];
        __syncthreads();
    }
    Pd[Row * width + Col] = Pvalue;
}

Problem type 3: __syncthreads()

  • Barrier within a block: every calling thread waits until all threads of the block reach that point. It does not synchronise different blocks (across blocks: split the kernel / CUDA 9+ cooperative groups).
  • It must be executed by all threads of the block. Using it inside an if/else is undefined behaviour (deadlock/wrong result); the only exception is when the condition evaluates the same for all threads of the block.
  • It is lightweight; since the threads of a block are assigned to the same SM together, waiting times stay short.
  • Slide note: it actually synchronises warps, not threads.
  • The two barriers in tiled matmul: 1. after the writes: nobody reads before the tile is full (read-after-write). 2. after the computation: nobody overwrites with the next phase's data before the others are done (write-after-read).
if (threadIdx.x < 16) {
    s[threadIdx.x] = in[threadIdx.x];
    __syncthreads();   // tid ≥ 16 never gets here
}
out[threadIdx.x] = s[threadIdx.x % 16];

if (threadIdx.x < 16)
    s[threadIdx.x] = in[threadIdx.x];
__syncthreads();
out[threadIdx.x] = s[threadIdx.x % 16];

An early return is the same trap: write if (row >= n) return; and then call __syncthreads(), and some threads never reach the barrier. Put the bounds check on the load/store lines (out-of-range threads write 0 into shared memory) and let everyone execute the barriers.

Problem type 4: Coalescing

  • Global memory is read in 32, 64 or 128-byte transactions; only segments aligned to their size can be read. There is no "reading 11 bytes": you read 32 bytes; 33 bytes = two 32 B accesses.
  • When a warp executes a global memory instruction, the accesses of its 32 threads are combined (coalesced) into one or more transactions. How many depends on (1) the word size per thread and (2) the distribution of the addresses over the threads.
  • The slide 47 calculation: 32 threads reading 4 B from random addresses move 32 × 32 B = 1024 B; reading consecutive, 128 B-aligned addresses moves 32 × 4 = 128 B, one transaction. 1024/128 = 8 times more data → bandwidth /8.
  • The word size should be 1, 2, 4, 8 or 16 B and naturally aligned (address a multiple of the size); otherwise it is split into several instructions. For structs: __align__(8), __align__(16).
  • 2D rule: if thread (tx, ty) accesses BaseAddress + width·ty + tx, full coalescing needs both the block width and the array width to be multiples of 32 → pad the rows with cudaMallocPitch.
  • Consecutive threads (threadIdx.x) should go to consecutive addresses: A[row*width + col] ✓, A[col*width + row] ✗.

Why the naive transpose is slow and how shared memory fixes it: Coalescing page. Summary:

// in: height×width, out: width×height
int x = blockIdx.x * TILE + threadIdx.x;  // column
int y = blockIdx.y * TILE + threadIdx.y;  // row
if (x < width && y < height)
    out[x * height + y] = in[y * width + x];
// x is consecutive within a warp: in is read
// consecutively, out is written 'height' apart

__shared__ float tile[TILE][TILE];
int x = blockIdx.x * TILE + threadIdx.x;
int y = blockIdx.y * TILE + threadIdx.y;
tile[threadIdx.y][threadIdx.x] = in[y * width + x];
__syncthreads();
x = blockIdx.y * TILE + threadIdx.x;   // blocks swap places
y = blockIdx.x * TILE + threadIdx.y;
out[y * height + x] = tile[threadIdx.x][threadIdx.y];
