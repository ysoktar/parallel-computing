CUDA quiz: çözümlü sorular

24 Kasım'daki yazılı CUDA quiz'i için hazırlanmış 31 soru; final için de iyi bir CUDA tekrarı. Sıra son konulardan başlar (L7 → L6 → senkronizasyon → tiling → CGMA → occupancy → kernel yazma → indeksleme). Her soruyu önce kendiniz çözün, sonra Çözümü göster.

Dört bağlantıyı birlikte düşünün: thread eşlemesi → warp adresleri → coalescing / divergence · karo boyutu → shared/register kullanımı → occupancy → latency hiding · veri yeniden kullanımı → CGMA → arithmetic intensity → bant genişliği tavanı · veri bağımlılığı → bariyer / atomic / ayrı kernel aşaması.

1. Hata kontrolü, divergence, predication (L7)

Soru 28 · Launch ve asenkron hata

Hata kontrolü olmayan k<<<g,b>>>(...); çağrısını tamamlayın. Peek ile Get farkı nedir?

// önce önceki tüm API hatalarını kontrol et (cudaGetLastError ile temizle)
k<<<g,b>>>(...);
cudaError_t launch = cudaGetLastError();     // != cudaSuccess ise raporla, dur
cudaError_t run = cudaDeviceSynchronize();   // != cudaSuccess ise raporla, dur

Launch hata kodu döndürmez. Get son hatayı alır ve cudaSuccess'a sıfırlar; Peek sıfırlamaz. Launch kontrolü konfigürasyon/parametre hatasını, sync kontrolü yürütme sırasında oluşan asenkron hatayı bulur. Bütün runtime çağrılarının dönüşleri de denetlenmeli. Çalışan örnek: 7.1.

Soru 29 · Predication, unrolling, blok sırası

Predication prediction'dan nasıl farklıdır? #pragma unroll 4 neden her zaman daha hızlı değildir? Normal (cluster'sız) blokların çalışma sırası neden garanti edilmez?

Prediction (CPU): dalı tahmin et, spekülatif yürüt, yanlışsa geri al. Predication (GPU): koşullu komutlar atlanmaz, thread başına predicate (mask) ile; false olanlar sonuç yazmaz, operand okumaz. Unroll döngü kontrolünü azaltır ama register baskısı ve kod boyutu artar (spill, düşük occupancy). Blokların bağımsızlığı donanımın onları farklı sayıda SM'ye serbestçe dağıtmasını sağlar; sıra garantisi bu esnekliği (ölçeklenebilirliği) bozar. CC 9.0 cluster'ları özel bir istisnadır.

Soru 24 · Divergence sayısı

Blok 128 thread, t = threadIdx.x: if (t < 70) ve if (t % 2 == 0) için kaç warp diverge olur? 16×16 2D blokta if (threadIdx.y % 2 == 0)?

t < 70: warp 0, 1 tamamen true; warp 2 (64–95) karışık; warp 3 false → 1. t % 2: 4 warp'ın hepsi karışık → 4. 16×16 blokta x hızlı değişir, her warp iki satırdır (biri çift biri tek) → 8 warp'ın hepsi. Farklı warp'ların farklı dal seçmesi divergence sayılmaz.

2. Global ve shared bellek erişimi (L6)

Soru 19 · Global memory transaction

32 lane'in her biri 4 B float okuyor: (a) 128 B hizalı ardışık 32 float; (b) tabandan 4 B kaydırılmış ardışık 32 float; (c) her lane ayrı bir 32 B segmentte. Taşınan veri ve verim? (32 B segment modeli)

Faydalı veri her durumda 128 B. (a) 4 segment = 128 B, %100. (b) bayt 4–131: 5 segment = 160 B, %80. (c) 32 segment = 1024 B, %12,5 (a'nın 1/8'i). Gerçek davranış mimariye bağlıdır.

Soru 20 · Matmul'da hangi erişim coalesced?

Row-major A, B; blok (32,8), bir warp bir çıktı satırına denk geliyor. A[r*K+k] ve B[k*N+c] erişimlerini karşılaştırın (k sabit bir komut adımı).

Warp içinde r ve k aynı: A'nın tek bir adresi tüm lane'lerce okunur (yeniden kullanım fırsatı). B'de c ardışık: 32 ardışık float, uygun hizalamayla coalesced. Tek bir thread'in zaman içinde B'nin sütununda dolaşması warp içi coalescing'i bozmaz: coalescing aynı komuttaki thread'ler arası adreslere bakar. Shared tiling ikisinde de tekrar eden global erişimi azaltır.

Soru 21 · Pitch

W = 100, H = 50 float; API pitch = 512 B döndürmüş. Satır 7, sütun 9'un tabana göre bayt ofseti? Ayrılan alan ve padding?

Ofset = 7·512 + 9·4 = 3620 B. Satırda gerçek veri 400 B, padding 112 B. Toplam 50·512 = 25600 B, mantıksal veri 20000 B, padding 5600 B. Erişim: ((float*)((char*)p + 7*pitch))[9]. Pitch bayt, sütun ofseti eleman cinsinden.

Soru 22 · Shared bank

Bir warp s[lane*k] okuyor (lane = threadIdx.x % 32, float s[], 32 bank). k = 1, 2, 3, 4, 16, 32, 33 için conflict derecesi? Herkes s[0] okursa?

EBOB(k, 32) = 1, 2, 1, 4, 16, 32, 1. k = 32: her lane farklı adres ama aynı bank → 32-yollu. k = 33 (padding): bank'lar dağılır. s[0]: aynı adres → yayın, conflict değil. Global segment ile shared bank farklı kavramlardır. Görselleştirme: 6.3, bank'lar.

Soru 26 · Bellek seçimi

(a) Thread'in toplayıcısı, (b) blokça paylaşılan karo, (c) tüm warp'ın aynı katsayıyı okuduğu filtre, (d) 2D yakınlık ve bilineer interpolasyon, (e) büyük, thread'e özel dizi: hangi bellek?

(a) register; (b) shared; (c) constant (yayın); (d) texture; (e) derleyici local memory'ye koyabilir (fiziksel olarak cihaz DRAM'i, hızlı değil). Surface yazılabilir; texture kernel içinden salt okunur.

Soru 27 · Derleme ve API

Runtime ve Driver API farkı? sm_70 ikilisi ve compute_70 PTX, 7.5 ve 8.6 GPU'larda nasıl davranır?

Runtime (cuda*): örtük context/modül yönetimi; Driver (cu*): açık, ayrıntılı kontrol. sm_70 ikilisi aynı major olan 7.5'te çalışır, 8.6'da çalışmaz (major farklı). compute_70 PTX iki GPU'da da sürücü tarafından JIT derlenebilir, ama yeni mimari özelliklerini kullanması garanti değildir. nvcc host ve device kodunu ayırır.

3. Senkronizasyon ve yarış

Soru 23 · Hatalı shared memory kernel'i

Aşağıdaki kodun sorunu nedir? Sınır dışı karo elemanları 0 olacak şekilde düzeltin.

if(i<N) {
    tile[threadIdx.x]=A[i];
    __syncthreads();
    B[i]=tile[(threadIdx.x+1)%blockDim.x];
}

Son blokta bazı thread'ler bariyere hiç ulaşmaz (tanımsız davranış) ve okunacak karo elemanı yüklenmemiş olabilir. Her thread karoyu doldurmalı ve bariyere ulaşmalı:

tile[threadIdx.x] = (i < N) ? A[i] : 0;                    // herkes kendi yerini doldurur (dışarıdaysa 0)
__syncthreads();                                            // bloktaki bütün thread'ler ulaşır
if (i < N) B[i] = tile[(threadIdx.x + 1) % blockDim.x];     // sağ komşuyu oku: onu BAŞKA bir thread yükledi

Aynı karo tekrar yüklenecekse okumalar bittikten sonra ikinci bir bariyer gerekir.

Soru 25 · Bariyer mi atomic mi?

sum += A[i]; __syncthreads(); ile blok içindeki toplam doğru olur mu? Bloklar da aynı sum'a yazarsa?

Hayır. += oku-değiştir-yazdır; bariyer sadece ilerleme sırasını eşgüdümler, kaybolan güncellemeyi engellemez. atomicAdd(&sum, A[i]) güncellemeyi atomik yapar. Alternatif: blok içi reduction, her blok için ayrı çıktı, ikinci bir kernel ile toplama. __syncthreads() bloklar arasında çalışmaz; __threadfence() grid bariyeri değildir.

4. Tiling ve yeniden kullanım (L5)

Soru 30 · Tiled kernel'i tamamla ve analiz et

N = 100 kare matrisler için 16×16 shared matmul yazın. SM: 48 KiB shared, 2048 thread, 64 warp, 16 blok, 65536 register; thread başına 32 register. Faz sayısı, bariyerler, occupancy?

#define T 16   // karo genişliği = blok genişliği
__global__ void matmul(const float* A, const float* B, float* C, int N) {
    __shared__ float a[T][T], b[T][T];
    int x = threadIdx.x, y = threadIdx.y;
    int r = blockIdx.y * T + y, c = blockIdx.x * T + x;      // bu thread'in C elemanı
    float s = 0;
    for (int p = 0; p < (N + T - 1) / T; p++) {               // faz p: A'nın satır şeridinin ve B'nin sütun şeridinin p. karoları
        int kx = p * T + x, ky = p * T + y;
        a[y][x] = (r < N && kx < N) ? A[r * N + kx] : 0;
        b[y][x] = (ky < N && c < N) ? B[ky * N + c] : 0;
        __syncthreads();                                      // (1) iki karo da doldu
        for (int k = 0; k < T; k++)
            s += a[y][k] * b[k][x];
        __syncthreads();                                      // (2) herkes bitirdi; sonraki faz üzerine yazabilir
    }
    if (r < N && c < N) C[r * N + c] = s;
}

Grid = (7,7), blok = (16,16), faz = ⌈100/16⌉ = 7; 12544 thread, 10000 geçerli. İlk bariyer yüklemeyi, ikincisi okumanın bitmesini garanti eder. Shared 2·16²·4 = 2048 B/blok. Limitler: thread 2048/256 = 8, warp 64/8 = 8, register 65536/(256·32) = 8, shared 24, blok 16 → 8 blok, %100 teorik occupancy. Sınır dışı lane'ler de bariyere katılır.

Soru 31 · Transpose optimizasyonu

Matris transpose'da global okumalar ardışık, yazmalar stride W. Shared memory ile ne yapılır?

Karoyu coalesced oku, bariyer, transpoze indekslerle coalesced yaz. 32×32 karoda shared sütun erişimi stride 32 → 32-yollu bank conflict; [32][33] padding giderir (32·1·4 = 128 B fazla shared). Global coalescing kazancı ile shared bank conflict'i ayrı değerlendirin; sınır kontrollerini bariyerin dışında tasarlayın. Bkz. transpose.

Soru 16 · Slayt 88: 1024×1024, 32×8 blok

Her thread bir çıktı; blok 32 sütun × 8 satır. Naive, sadece A shared, sadece B shared, ikisi shared durumlarında blok başına global okuma? (Sadece girdi okumaları, ideal yeniden kullanım.)

Blok başına 256 çıktı, her biri 1024 A + 1024 B okur. A'nın aynı satırını 32 thread, B'nin aynı sütununu 8 thread paylaşır.

Soru 17 · Karo boyutu ve faz

A = 64×96, B = 96×128; kare T = 16. Kaç faz, blok, blok başına shared bayt ve girdi okuması? T = 32'ye geçince?

T16: faz = 96/16 = 6, grid = (8,4) = 32 blok, shared 2·16²·4 = 2048 B, okuma/blok = 6·2·256 = 3072, toplam 98304. T32: faz 3, grid (4,2) = 8 blok, shared 8192 B, okuma/blok 6144, toplam 49152: trafik yarıya iner ama 1024 thread/blok ve 8 KiB shared ile kaynak sınırları kontrol edilmeli.

Soru 18 · Dikdörtgen karo

Çıktı H = 8, W = 32, faz derinliği D = 16. Kaç float shared gerekir? 256 thread'e yükü nasıl dağıtırsınız?

A karosu 8·16 = 128, B karosu 16·32 = 512; toplam 640 float = 2560 B. 256 thread lineer kimlik t ile A ve B karolarını ayrı for (i = t; i < count; i += 256) döngüleriyle doldurur; bariyer; her thread D = 16 çarp-topla; tekrar bariyer. Dikdörtgen bloğun boyutlarını kare karo koduna doğrudan koymak hatalıdır.

5. CGMA ve bant genişliği

Soru 13 · G80 örneği

Tepe 367 GFLOP/s, BW 86,4 GB/s, float 4 B. CGMA = 1, 8, 16, 32 için ideal tavan?

86,4/4 = 21,6 G float/s; P = min(367, 21,6·CGMA): 21,6 · 172,8 · 345,6 · 367 (32'de bellek tavanı 691,2 ama hesap tepesi 367). Hesap sınırına geçiş CGMA ≥ 367/21,6 ≈ 17.

Soru 14 · Matmul: FLOP ve trafik

N = 256, T = 16. Naive ve tiled'da global okuma, çıktı yazma, FLOP ve CGMA?

FLOP = 2N³ = 33.554.432. Naive okuma = 2N³ = 33.554.432; tiled = 2N³/T = 2.097.152. Yazma N² = 65.536. Sadece okuma: CGMA 1 ve 16. Yazma dahil: ≈ 0,998 ve ≈ 15,52.

Soru 15 · Hesap mı bellek mi sınırlı?

BW = 320 GB/s, tepe 8 TFLOP/s. Kernel çıktı başına 40 FLOP, 10 float okuma, 1 float yazma yapıyor. Tavan?

CGMA = 40/11 ≈ 3,64; FLOP/bayt = 40/44 ≈ 0,909. Pbellek = 320 · 0,909 ≈ 290,9 GFLOP/s ≪ 8000 → bellek sınırlı.

6. Occupancy ve SM kaynakları

Soru 9 · GT200 blok seçimi

SM başına 1024 thread, 8 blok; blok başına 512 thread. 8×8, 16×16, 32×32?

8×8: 8 blok × 64 = 512 thread, %50. 16×16: 4 blok = 1024, %100. 32×32 = 1024 > 512: geçersiz. 16×16 bu cihaz için en iyi aday (performans garantisi değil).

Soru 10 · Limitler birlikte

SM: 2048 thread, 64 warp, 16 blok, 65536 register, 48 KiB shared. Blok 256 thread, 48 register/thread, 12 KiB shared. Kaç blok, occupancy? Shared 8 KiB'ye düşerse?

Blok = 8 warp, 12288 register. Thread 8, warp 8, blok 16, register ⌊65536/12288⌋ = 5, shared 48/12 = 4 → 4 blok, 32 warp, %50. Shared 8 KiB: shared 6'ya izin verir ama register 5 ile sınırlar → 5 blok, 40 warp, %62,5. Bir darboğaz kalkınca başkası sınırlar.

Soru 11 · Kısmi warp tuzağı

SM: 64 warp, 2048 thread, 32 blok. Blok 48 thread. Occupancy?

Blok başına ⌈48/32⌉ = 2 warp. Thread ⌊2048/48⌋ = 42, warp 64/2 = 32, blok 32 → 32 blok × 2 = 64 warp → %100 warp occupancy, ama 1536/2048 = %75 aktif thread. Kısmi warp tam bir warp slotu kaplar.

Soru 12 · Spill mi occupancy mi?

Kernel thread başına 64 register kullanıyor. Register baskısı artınca ne olabilir?

(1) Register kapasitesi daha az bloğa izin verir (düşük occupancy). (2) Derleyici sığdıramadığı değerleri local memory'ye spill eder (DRAM trafiği). Bunlar farklı olaylardır; register'ı zorla azaltıp occupancy'yi artırmak spill yüzünden daha yavaş da olabilir.

7. Kernel yazma ve host-device akışı

Soru 5 · Vektör işlemi

C[i] = 2A[i] + B[i] hesaplayan kernel'i ve launch'ı yazın; cudaMemcpy yönlerini belirtin.

__global__ void f(const float* A, const float* B, float* C, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) C[i] = 2 * A[i] + B[i];
}
cudaMemcpy(dA, A, bytes, cudaMemcpyHostToDevice);   // bytes = N * sizeof(float)
cudaMemcpy(dB, B, bytes, cudaMemcpyHostToDevice);
f<<<(N + 255) / 256, 256>>>(dA, dB, dC, N);           // dC'ye kopyalamak gerekmez: her elemanı yazılır
cudaMemcpy(C, dC, bytes, cudaMemcpyDeviceToHost);

Çıktı tamamen yazılacağından dC'ye H2D gerekmez. Çıktı başına 2 FLOP, 2 okuma + 1 yazma → tüm erişimlerle CGMA = 2/3.

Soru 6 · Dikdörtgen matris çarpımı

A = 35×19, B = 19×65, 16×16 blok. Kernel ve launch?

__global__ void mm(const float* A, const float* B, float* C, int M, int K, int N) {
    int r = blockIdx.y * blockDim.y + threadIdx.y;   // C'nin satırı
    int c = blockIdx.x * blockDim.x + threadIdx.x;   // C'nin sütunu
    if (r >= M || c >= N) return;
    float s = 0;
    for (int k = 0; k < K; k++)
        s += A[r * K + k] * B[k * N + c];
    C[r * N + c] = s;
}
mm<<<dim3(5, 3), dim3(16, 16)>>>(dA, dB, dC, 35, 19, 65);   // ⌈65/16⌉ = 5 sütun, ⌈35/16⌉ = 3 satır blok

C = 35×65 = 2275 çıktı; grid (⌈65/16⌉, ⌈35/16⌉) = (5,3), 3840 thread, 1565 boş. Tuzak: A'nın satır adımı 19, B ve C'ninki 65; hepsini aynı width ile indekslemek yanlış.

Soru 7 · 3×3 Gauss konvolüsyonu

W×H görüntüye (1/16)·[1 2 1; 2 4 2; 1 2 1] filtresini zero padding ile uygulayan kernel; blok boyutu parametre.

__constant__ float F[9];   // host'tan cudaMemcpyToSymbol ile doldurulur
__global__ void conv(const float* in, float* out, int W, int H) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;   // sütun
    int y = blockIdx.y * blockDim.y + threadIdx.y;   // satır
    if (x >= W || y >= H) return;
    float sum = 0;
    for (int dy = -1; dy <= 1; dy++) {
        for (int dx = -1; dx <= 1; dx++) {
            int xx = x + dx, yy = y + dy;                       // komşu
            if (xx >= 0 && xx < W && yy >= 0 && yy < H)         // görüntü dışı 0 sayılır
                sum += in[yy * W + xx] * F[(dy + 1) * 3 + dx + 1];
        }
    }
    out[y * W + x] = sum;
}
cudaMemcpyToSymbol(F, hF, 9 * sizeof(float));
dim3 b(BX, BY), g((W + BX - 1) / BX, (H + BY - 1) / BY);
conv<<<g, b>>>(dIn, dOut, W, H);

Filtre katsayısı warp içinde aynı döngü adımında aynı adres → constant yayını uygun. Sınır dışı girdi 0. 16×16 karo için halo dahil shared alan (16+2)² = 324 float = 1296 B.

Soru 8 · Kernel ve uçtan uca speedup

CPU 80 ms, H2D 6 ms, kernel 4 ms, D2H 10 ms. İki hızlanma? %95 paralel kod için Amdahl üst sınırı?

Sadece kernel: 80/4 = 20×. Uçtan uca: 80/(6+4+10) = 4×. Amdahl: 1/0,05 = 20× (ayrı ideal model). Host kronometresiyle ölçerken kernel bitişini beklemek gerekir.

8. Thread, blok ve indeksleme

Soru 1 · 1D launch ve taşan thread'ler

N = 1000, blok başına 128 thread. Grid, toplam thread, geçersiz thread, warp sayısı, blok 5 thread 37'nin indeksi?

Grid ⌈1000/128⌉ = 8; 1024 thread, 24 sınır dışı. Blok başına 4 warp, toplam 32. İndeks 5·128 + 37 = 677; yerel warp 1, lane 5. Son blokta 104 geçerli thread. if (i < 1000) şart.

Soru 2 · 2D eşleme

130 sütun × 75 satır, blok (16,8). Grid, toplam thread; blockIdx=(3,4), threadIdx=(7,5) için (x,y), row-major indeks, warp, lane?

Grid (9,10), 90 blok × 128 = 11520 thread, 9750 geçerli. x = 55, y = 37, indeks 37·130 + 55 = 4865. Yerel 5·16 + 7 = 87 → warp 2, lane 23. Her warp iki 16'lık satıra yayılır.

Soru 3 · 3D eşleme

Hacim W = 40, H = 30, D = 20; blok (8,4,2). blockIdx=(2,3,4), threadIdx=(5,2,1) için global ve yerel lineer indeks?

x = 21, y = 14, z = 9. Global = 21 + 40·(14 + 30·9) = 11381. Yerel = 5 + 8·(2 + 4·1) = 53 → warp 1, lane 21. Grid (5,8,10) = 400 blok, 25600 thread, 24000 geçerli.

Soru 4 · Neden blockIdx gerekli?

int i = threadIdx.x; kullanan 8 bloklu vektör toplama neden yanlış?

Bütün bloklar aynı threadIdx aralığına sahip: hepsi ilk 128 elemanı tekrar işler, diğerleri hiç yazılmaz; aynı yere eş zamanlı yazma da olur. Doğrusu i = blockIdx.x*blockDim.x + threadIdx.x; ve sınır kontrolü.

Son kontrol

Şunları karıştırmayın: warp içi erişim ↔ bir thread'in ardışık zaman adımları; local ↔ shared; CGMA ↔ transaction; occupancy ↔ speedup; bariyer ↔ atomic; coalescing (global) ↔ bank conflict (shared); predication ↔ prediction. Soruda eski bir mimari verilirse onun sayısal limitlerini kullanın.
