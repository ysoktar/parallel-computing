3. Tiled matmul: W×W, T×T, W % T = 0

__shared__ float Mds[T][T], Nds[T][T];
int row=blockIdx.y*T+ty, col=blockIdx.x*T+tx;
float sum=0;
for (int m=0; m<W/T; ++m) {
  Mds[ty][tx] = M[row*W + m*T + tx];
  Nds[ty][tx] = N[(m*T + ty)*W + col];
  __syncthreads();                // tile ready
  for (int k=0;k<T;++k) sum+=Mds[ty][k]*Nds[k][tx];
  __syncthreads();                // tile may be overwritten
}
P[row*W+col]=sum;

W=matris genişliği, T=karo kenarı (bu örnekte blockDim.x=blockDim.y=T); tx=threadIdx.x, ty=threadIdx.y; m=phase (yüklenen karo numarası, 0'dan başlar), k=karo içi çarpım indeksi (0..T-1). Mds/Nds=shared karolar, sum=biriken sonuç. İlk bariyer yüklemeyi, ikinci yeniden kullanımı korur.

5. __syncthreads() kuralları

// wrong: divergent barrier
if (tid<16) { s[tid]=v; __syncthreads(); }
// correct:
if (tid<16) s[tid]=v;
__syncthreads();
// load → sync → use → sync → next load

Blok bariyeridir; tüm katılan thread'ler erişmeli. Shared yazma→başka thread okuma için sync; erken return/ayrışan if tehlikeli.

32 lanes × float(4 B) = 128 B requested
aligned a[lane] → 4×32 B segments (128 B)

lane=warp içi thread sırası (0–31), float=4 B; 32 B=örnek hizalı bellek segmenti, her GPU'da cache-line boyutu demek değildir. Satır-major A[row*W+col]; row/col=matris koordinatları, W=sütun sayısı; pitchBytes=bayt cinsinden satır adımı, W*4'ten büyük olabilir. Gerçek işlemler cache'e bağlıdır.

8. Transpose: adresin yönü

// A and B: N×N, row-major
naive: B[col*N+row] = A[row*N+col];
read: adjacent col → contiguous
write: adjacent col → stride N
shared (T=32, block=32×32):
tile[ty][tx] = A[(by*T+ty)*N + bx*T+tx];
__syncthreads();
B[(bx*T+ty)*N + (by*T+tx)] = tile[tx][ty];

bx=blockIdx.x, by=blockIdx.y (blok koordinatları); tx=threadIdx.x, ty=threadIdx.y (blok içi thread); T=karo boyutu, N=matrisin sütun sayısı. A→B satır/sütun takas eder. Naive yazma adresi N eleman atlayabilir.

Coalescing: warp erişimleri ve transpose'ı tek tek say

// Warp: 32 threads; lane = 0..31; float=4 B
// Assume base address aligned to 32 B.
A[lane]       : offsets 0,4,...,124 B -> 4 segments =128 B
A[lane+1]     : offsets 4,8,...,128 B -> 5 segments =160 B
A[2*lane]     : offsets 0,8,...,248 B -> 8 segments =256 B
A[8*lane]     : offsets 0,32,...,992 B -> 32 segments =1024 B
A[1024*lane]  : offsets 0,4096,... -> 32 segments =1024 B
// Actual cache hits and transaction counts depend on GPU.
// Row-major matrix: A[row*W+col] (W = column count)
// x-neighbor threads -> col+1 -> +4 B: contiguous.
// Naive transpose: B[col*H+row] (H = output width)
// x-neighbor threads -> col+1 -> +4*H B: strided.

32 thread × 4 B = 128 B faydalı veri. Ardışık A[lane] erişimi 32 B hizalı dört segmente dokunur (4×32=128 B). Her ikinci eleman A[2*lane] sekiz segmente (256 B), çok uzak adresler A[1024*lane] ise 32 ayrı segmente (1024 B) dokunur. Bu, gerçek cache-line boyutu veya kesin GPU transaction sayısı değildir.

Matris adresi: A[row*W+col], burada W=matris sütun sayısı. Komşu x-thread col değerini 1 artırınca adres +4 bayt ilerler. Transpose: A'nın boyutu H×W ise B'nin boyutu W×H olur; yazma B[col*H+row]. Ardışık x-thread'lerde B adresi +4×H bayt zıplar. Coalescing kötüleşebilir.

Cache ile fark: Coalescing warp'ın adres düzenidir; L1/L2 cache hit/miss donanımda verinin bulunma durumudur. Bunlar aynı kavram değildir. pitchBytes hizalı satır adımıdır, float adres hesabında önce bayt eklenir.

Hızlı kontrol: transpose ve bellek

H=3, W=4, row=1, col=2 ise giriş A[1*4+2]=A[6], çıkış B[2*3+1]=B[7]. L1 cache her SM'de, L2 cache tüm SM'ler arasında ortaktır.

Mutex neyi önler? Bir sayaç üzerinde iki thread

#include <mutex>
std::mutex m; // shared lock
int counter=0; // shared data
void increment(){
  std::lock_guard<std::mutex> hold(m); // lock
  ++counter; // protected critical section
} // hold destroyed => unlock

Adım adım: (1) counter=0. (2) T0 m mutex'ini kilitler. (3) T1 aynı m için bekler. (4) T0 counter++ ile 1 yazar, scope sonunda lock_guard açar. (5) T1 kilidi alır, 2 yazar. Sonuç 2. Mutex yoksa iki thread 0 okuyup 1 yazabilir; C++'ta veri yarışı tanımsız davranıştır.

Değişkenler: m=tek sahipli mutex; counter=iki thread'in paylaştığı tamsayı; hold=RAII koruyucu nesne; lock_guard kapsam bittiğinde kilidi bırakır. lock kilidi alır, unlock bırakır; lock_guard bunları senin adına yönetir.

Producer–consumer: mutex, condition_variable ve semafor

#include <mutex>
#include <condition_variable>
#include <queue>
std::mutex m;
std::condition_variable cv;
std::queue<int> q; bool finished=false;
void produce(int value) {
  { std::lock_guard<std::mutex> lock(m);
    q.push(value); }
  cv.notify_one();
}
int consume() {
  std::unique_lock<std::mutex> lock(m);
  cv.wait(lock, [] { return !q.empty() || finished; });
  if(q.empty()) return -1; // finished, no work
  int v=q.front(); q.pop(); return v;
}
// When ending, set finished=true WITH m locked,
// then cv.notify_all(). -1 is the end marker.

Producer (üretici) value'yu kuyruğa (q) ekler; mutex m kuyruğu korur; cv.notify_one() bekleyen tüketicilerden birini haberdar eder. Consumer (tüketici) cv.wait(lock, koşul) yapar: beklerken mutex'i bırakır, uyanınca yeniden kilitler ve koşulu kontrol eder. Böylece boş kuyruğu okuyup hata yapmaz.

Değişkenler: q=FIFO kuyruk, m=mutex, cv=condition variable, finished=üretim bitti mi, v=tüketilen değer. unique_lock, wait'ın kilidi bırakıp yeniden alabilmesi için gerekir. std::counting_semaphore<3> permits(3) ise en çok 3 işi eşzamanlı içeri alır; tek başına q veya counter korumaz.

#include <semaphore>
#include <mutex>
std::counting_semaphore<3> permits(3); // 3 slots
std::mutex m; int counter=0;
void job(){
  permits.acquire(); // 3 jobs may enter
  { std::lock_guard<std::mutex> guard(m);
    ++counter; } // only 1 writes at a time
  doWorkNoThrow(); // illustrative: no exception
  permits.release(); // return slot
}

Deadlock, starvation, livelock ve çözümü

std::mutex m1, m2;
// Bad: T0 locks m1 -> waits m2
//      T1 locks m2 -> waits m1
void safe(){ std::scoped_lock both(m1,m2);
  // both locks acquired without circular wait
}
// std::unique_lock is movable and supports
// unlock()/lock(); used by condition_variable.

Deadlock: T0, m1'i tuttuğu sırada m2'yi bekler; T1 m2'yi tutarken m1'i bekler. İkisi de ilerleyemez. std::scoped_lock both(m1,m2) iki mutex'i deadlock'tan kaçınan kilitleme mekanizmasıyla edinir. Alternatif: bütün thread'ler kilitleri tutarlı sırada alsın.

Starvation: bir thread sürekli CPU/kilit sırası alamaz. Livelock: thread'ler işlem yapar ama faydalı ilerleme olmaz. unique_lock hareket ettirilebilir ve geçici olarak açılabilir; condition_variable::wait ile kullanılır.

3. Mutex, lock_guard ve semaphore aynı şey değil

#include <mutex>
#include <semaphore>
std::mutex m;
std::counting_semaphore<3> slots(3);
int counter=0;
void job(){
  slots.acquire(); // at most 3 jobs enter
  { std::lock_guard<std::mutex> hold(m);
    ++counter; }  // only 1 thread modifies it
  doWork();
  slots.release();
}
// Without mutex, 3 concurrent increments may race.

Fark: Semaphore aynı anda 3 işe izin verebilir; bu, counter++ için karşılıklı dışlama sağlamaz. mutex tek kilit sahibine izin verir. lock_guard kapsam sona erdiğinde mutex'i otomatik açar.

Sözel cevap: İki thread m1→m2 ve m2→m1 sırasıyla kilit beklerse deadlock olabilir. Starvation bir thread'in sürekli geride bırakılmasıdır. Bir C++ data race için belirli çıktı garanti edilmez.

4. Coalescing: adres sıralaması ve 32 B segment

32 lanes, float=4 B, aligned base=0
lane i: A[i]        -> 0,4,8,...,124 B
  covered segment numbers: 0,1,2,3 (4×32B)
lane i: A[2*i]      -> 0,8,16,...,248 B
  segments: 0..7 (8×32B)
lane i: A[1024*i]   -> spacing=4096 B
  segments: 32 distinct (32×32B = 1024B)
A[row*W+col] -> if col changes +1, address +4B

Neden: Satır-major bellekte yan yana threadIdx.x lane'leri yan yana sütunları okursa 128 baytlık istek dört 32 B segmente sığar. row değişirken W ile çarpılan adresler uzaklaşır.

Önemli: Bu sayılar hizalı 32 B segment öğretim modeli içindir; gerçek GPU'nun cache ve bellek transaction davranışı donanımına bağlıdır. Pitch bayt cinsindendir: base + row*pitchBytes + col*4.

5. Tiled matmul: bir thread'in bir fazda ne yüklediği

N=32; T=8; blockIdx=(1,0);
threadIdx=(2,3); phase=1
row=0*8+3=3; col=1*8+2=10
Mds[3][2] <- M[3][1*8+2] = M[3][10] = M[106]
Nds[3][2] <- N[1*8+3][10] = N[11][10] = N[362]
__syncthreads(); // all shared tiles loaded
for(k=0;k<8;k++) sum+=Mds[3][k]*Nds[k][2];
__syncthreads(); // next phase must not overwrite
P[3*32+10] = P[106] <- accumulated 4 phases

Bir thread bir fazda yalnız iki global değer yükler fakat 8 çarpım-toplama yapar; diğer 63 thread karonun kalan değerlerini yüklediğinden shared bellek yeniden kullanılır. phase=0,1,2,3 olmak üzere dört faz vardır.

İki bariyer: İlk __syncthreads() tüm yüklemeler bitmeden okumayı önler (RAW). İkincisi diğer thread'lerin hâlâ kullandığı karonun sonraki fazda ezilmesini önler. Bariyeri ayrışan if içine koyma.

6. Transpose: aynı değer, farklı lineer indeks

A is 3×5 (H=3,W=5), B is 5×3
A[row=1][col=3] => A[1*5+3] = A[8]
B[col=3][row=1] => B[3*3+1] = B[10]
__global__ void trans(float*A,float*B,int H,int W){
  int row=blockIdx.y*blockDim.y+threadIdx.y;
  int col=blockIdx.x*blockDim.x+threadIdx.x;
  if(row<H && col<W) B[col*H+row]=A[row*W+col];
}

Neden: A genişliği 5, B genişliği 3'tür. Değerin satır/sütun koordinatları yer değiştirir. Komşu x-lane'ler A'yı ardışık okuyabilir fakat B'ye yazarken H elemanlık stride ile ayrılır.

Sınav yöntemi: Önce çıktı matrisinin boyutunu yaz (W×H); sonra hedefin lineer adresini hedef matrisin yeni genişliği ile çarp.

İlgili deneme sorusunu çöz

Sık yapılan hatalar: localID global matris indeksi değildir; for değişkeni threadIdx değildir; semaphore tek başına kritik bölüm koruması değildir; ayrışan blok bariyeri hatalıdır; yüksek occupancy her zaman daha hızlı değildir. Tam 120 dakikalık kod yazmalı denemeyi aç.

Yazma ipuçları: ince uçlu kalem; formülleri değişken adlarıyla kısaltın (bx, by, tx, ty, T, W); kod satırlarını tam yazın (sınavda kod yazdırılabilir); iki küçük çizim yapın: 8×32 blokta warp şekli ve faz m'de M/N karoları. Sayıları "hesap makinesi yok" diye hazır yazın.

5. __syncthreads() kuralları

  • Sadece blok içi bariyer; bloklar arası yok (kernel'i böl / cooperative groups, CUDA 9+).
  • Bloktaki tüm thread'ler çalıştırmalı. if içinde ya da erken return sonrası = tanımsız (koşul herkes için aynıysa hariç).
  • Başka thread'in yazdığı shared veriyi okumadan önce şart. Aslında warp'ları senkronize eder.
  • ✗ if (tid<16){ s[tid]=..; __syncthreads(); } → ✓ if (tid<16) s[tid]=..; __syncthreads();
