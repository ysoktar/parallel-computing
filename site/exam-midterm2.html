Ezberlenecek indeks formülleri

// 2D grid + 2D blok: her thread bir (row, col) elemanı int col = blockIdx.x * blockDim.x + threadIdx.x; // x → sütun (ardışık bellek) int row = blockIdx.y * blockDim.y + threadIdx.y; // y → satır A[row * width + col] // row-major: satır * genişlik + sütun // bloktaki lineer thread numarası (warp'ı bu belirler: warp = id / 32) 1D: id = threadIdx.x 2D: id = threadIdx.y * blockDim.x + threadIdx.x 3D: id = threadIdx.z * blockDim.x * blockDim.y + threadIdx.y * blockDim.x + threadIdx.x // grid'i kapsayacak blok sayısı (yukarı yuvarlama) + sınır kontrolü dim3 block(16, 16); dim3 grid((width + block.x - 1) / block.x, (height + block.y - 1) / block.y); if (row < height && col < width) { ... }

dim3(a, b)'de önce x sonra y gelir. dim3(8, 32): blockDim.x = 8 (8 sütun), blockDim.y = 32 (32 satır). x ekseni sütunlar, y ekseni satırlardır; warp'lar threadIdx.x en hızlı değişecek şekilde oluşturulur.

Soru tipi 1: Hangi indeks nereyi gösteriyor?

Geçmiş yıl sorusu: "<<<(3,3),(8,32)>>> ile tiled matris çarpımı eşlemesi". Aşağıdaki çözüm bu tipteki her soruyu kapsayacak şekilde adım adım gidiyor.

Çözümlü örnek: <<<dim3(3,3), dim3(8,32)>>>

__global__ void MatMul(const float* M, const float* N, float* P, int K, int Pcols)
{
    int row = blockIdx.y * blockDim.y + threadIdx.y;   // 0..95
    int col = blockIdx.x * blockDim.x + threadIdx.x;   // 0..23
    float sum = 0;
    for (int k = 0; k < K; ++k)
        sum += M[row * K + k] * N[k * Pcols + col];
    P[row * Pcols + col] = sum;
}
// MatMul<<>>(Md, Nd, Pd, K, 24);
  1. Kaç thread, kaç warp? Blok başına 8·32 = 256 thread (≤ 1024 ✓), 3·3 = 9 blok → 2304 thread. Blok başına 256/32 = 8 warp → toplam 72 warp.
  2. İndeks aralıkları: blockIdx.x, blockIdx.y ∈ {0,1,2}, threadIdx.x ∈ 0..7, threadIdx.y ∈ 0..31.
  3. Kapsanan P bölgesi: sütun = 3·8 = 24, satır = 3·32 = 96. Yani P 96×24 ise birebir oturur (M 96×K, N K×24). Matris daha küçükse if (row < H && col < W) şart; daha büyükse grid büyütülmeli.
  4. Belli bir thread: blockIdx = (2,1), threadIdx = (5,10) → row = 1·32 + 10 = 42, col = 2·8 + 5 = 21. P[42·24 + 21] = P[1029]'u yazar; M'nin 42. satırını (M[42·K + k]), N'nin 21. sütununu (N[k·24 + 21]) okur.
  5. Hangi blok hangi bölge? blockIdx = (bx, by) bloğu satır 32·by … 32·by+31, sütun 8·bx … 8·bx+7. Örneğin (2,1): satır 32–63, sütun 16–23.
  6. Warp'lar: bloktaki lineer id ty·8 + tx. Warp 0 = id 0–31 = ty = 0..3 (her biri 8 thread). Yani bir warp P'nin 4 satır × 8 sütunluk bir parçası. Warp w: ty = 4w … 4w+3.
  7. Coalescing (k sabitken bir warp'ın bir load'u):
    • N[k·24 + col]: aynı satırdaki 8 thread 8 ardışık float okur (32 B); warp'taki 4 satır aynı adresleri okur → 1 adet 32 B segment. İyi.
    • M[row·K + k]: aynı satırdaki 8 thread aynı adresi okur; 4 satır 4 farklı adres (aralarında K float) → 4 segment, her birinden 4 bayt kullanılır. Kötü (ama önbellek/yayın yardımcı olur).
    • P[row·24 + col] yazma: 4 satır × 8 ardışık float → 4 ayrı 32 B segment. 128 B'lık tek bir transaction yerine 4 parça; slayt kuralı: blok genişliği ve dizi genişliği warp boyunun (32) katı olsun. blockDim.x = 8 bu yüzden ideal değil.

Aynı konfigürasyonla tiled (shared memory) versiyon

Slayttaki tiled kernel TILE_WIDTH × TILE_WIDTH kare blok varsayar (Mds[ty][tx], Nds[ty][tx], her thread her matristen 1 eleman). 8×32 blokta bu doğrudan çalışmaz; P karosu 32 satır × 8 sütun. Faz genişliğini (k yönü) TK = 8 seçersek:

#define BX 8    // blockDim.x  = P karosunun sütun sayısı
#define BY 32   // blockDim.y  = P karosunun satır sayısı
#define TK 8    // her fazda k yönünde alınan genişlik

__global__ void MatMulTiled(const float* M, const float* N, float* P, int K, int Pcols)
{
    __shared__ float Mds[BY][TK];   // 32×8 = 256 eleman: her thread 1 tane yükler
    __shared__ float Nds[TK][BX];   //  8×8 =  64 eleman: sadece ty < 8 olanlar yükler
    int tx = threadIdx.x, ty = threadIdx.y;
    int row = blockIdx.y * BY + ty;
    int col = blockIdx.x * BX + tx;
    float sum = 0;
    for (int m = 0; m < K / TK; ++m) {
        Mds[ty][tx] = M[row * K + (m * TK + tx)];
        if (ty < TK)
            Nds[ty][tx] = N[(m * TK + ty) * Pcols + col];
        __syncthreads();                  // karolar tamamen dolsun (if'in DIŞINDA!)
        for (int k = 0; k < TK; ++k)
            sum += Mds[ty][k] * Nds[k][tx];
        __syncthreads();                  // herkes bitirmeden bir sonraki faz üzerine yazmasın
    }
    P[row * Pcols + col] = sum;
}
  • Shared bellek/blok: (32·8 + 8·8)·4 B = 1280 B.
  • Global okuma: bir blok M'den 32×K, N'den K×8 eleman okur = 40K; naive versiyonda 256 thread × 2K = 512K. Azalma 512/40 = 12,8×. Genel formül (BX×BY blok): 2·BX·BY / (BX + BY); kare T×T için bu T'ye iner (slayttaki "16×16 → 16 kat").
  • Alternatif: TK = 32 ile Mds[32][32] (her thread 4 eleman yükler) ve Nds[32][8] (her thread 1). Faz sayısı azalır, shared bellek artar. Sınavda hangisini seçerseniz seçin kim neyi yüklüyor ve iki __syncthreads() açıkça yazılmalı.

"Bu kod nerelere dokunuyor?" alıştırmaları

Her birinde önce kendiniz cevaplayın, sonra çözümü açın.

(a) A 8×8 row-major, k<<<2, 4>>>(A, 8):

__global__ void k(float* A, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 0..7
    A[i * N] = 0;
}

i = 0..7, adres 8i: A[0], A[8], …, A[56]. Bu 0. sütun. Ardışık thread'ler 8 float (32 B) aralıklı adreslere yazar → her thread ayrı bir 32 B segment: coalesced değil. A[i] yazsaydık 0. satır olurdu ve coalesced olurdu.

(b) B 16×16 (width = 16), k2<<<dim3(2,2), dim3(8,8)>>>:

__global__ void k2(int* B, int width) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    B[x * width + y] = threadIdx.x;      // dikkat: x satır gibi kullanılmış!
}

Bütün 16×16 matris kapsanır (2·8 = 16 her yönde), ama transpoze edilmiş şekilde: thread (x, y) satır x, sütun y'ye yazar. blockIdx=(1,0), threadIdx=(3,5) → x = 11, y = 5 → B[11·16 + 5] = B[181]'e 3 yazar. Bir warp'ta threadIdx.x ardışık değişir → adresler 16 eleman (64 B) aralıklı → coalesced değil. Düzeltme: B[y * width + x]. Değer olarak her elemana kendi satır içindeki threadIdx.x = x % 8 yazılır; yani B'nin satır r'sindeki her eleman r % 8 olur.

(c) <<<4, 256>>> ile çağrılan bir kernelde blockIdx.x = 2, threadIdx.x = 37 olan thread hangi warp'ta, global id'si ne, a[2*i] okursa ne olur?

Global id i = 2·256 + 37 = 549. Bloğunun 1. warp'ı (37/32 = 1, warp'lar blok içinde numaralanır; bloklar warp paylaşmaz). a[2*i]: ardışık thread'ler 8 B aralıklı → warp 32 float'ı 256 B'lık bir alana yayar → 128 B'lık 2 satır (ya da 32 B'lık 8 segment) taşınır, yarısı kullanılır: %50 verim.

Soru tipi 2: Shared memory kullanımı

  • __shared__ float s[N]; kernel içinde tanımlanır; blok başına bir kopya, bloktaki tüm thread'ler aynısını görür, ömrü kernel/blok kadar.
  • On-chip, çok hızlı (register'dan sonra en hızlısı); küçük (G80'de SM başına 16 KB).
  • Kullanım deseni: (1) global'den shared'a işbirliğiyle yükle (her thread birkaç eleman), (2) __syncthreads(), (3) shared'dan tekrar tekrar oku/hesapla, (4) gerekirse __syncthreads(), (5) sonucu global'e yaz.
  • Amaç: global bellek trafiğini azaltmak (CGMA'yı artırmak) ve thread'lerin veri paylaşması. "Shared memory = user-controlled cache."
  • Başka blok bir bloğun shared belleğini göremez; bloklar arası iletişim global bellekle olur.
#define B 256
__global__ void reverseBlock(int* d)
{
    __shared__ int s[B];
    int t = threadIdx.x;
    int base = blockIdx.x * B;
    s[t] = d[base + t];          // 1) yükle
    __syncthreads();             // 2) herkes yükledi mi?
    d[base + t] = s[B - 1 - t];  // 3) BAŞKA thread'in
}                                //    yüklediğini oku
// reverseBlock<<>>(d);

Yukarıdaki __syncthreads() kaldırılırsa thread t, s[B-1-t]'yi başka bir warp'taki thread henüz yazmadan okuyabilir: race condition, sonuç belirsiz. Bir thread shared bellekten başka bir thread'in yazdığı veriyi okuyacaksa arada mutlaka bariyer olmalı.

"Önce işlem yapmadan sadece kopyala." Shared memory'ye, yazacağınız bölgenin dışından da veri (ör. konvolüsyonda kenar/halo bölgesi) gerekiyorsa: önce kernel'i sadece "global → shared → global" kopyası yapacak şekilde yazın ve çıktının girdiyle aynı olduğunu doğrulayın. İndeksler doğruysa hesaplamayı sonra ekleyin. Sınavda da shared'a yükleme indekslerini ayrı ayrı kontrol edin.

Tiled matris çarpımının tamamı, faz faz görselleştirmesiyle: L5 sayfası. Kısa hâli:

__global__ void MatrixMulKernel(float* Md, float* Nd, float* Pd, int width)
{
    __shared__ float Mds[TILE_WIDTH][TILE_WIDTH];
    __shared__ float Nds[TILE_WIDTH][TILE_WIDTH];
    int bx = blockIdx.x, by = blockIdx.y;
    int tx = threadIdx.x, ty = threadIdx.y;
    int Row = by * TILE_WIDTH + ty;
    int Col = bx * TILE_WIDTH + tx;
    float Pvalue = 0;
    for (int m = 0; m < width / TILE_WIDTH; ++m) {
        Mds[ty][tx] = Md[Row * width + (m * TILE_WIDTH + tx)];   // M: satır Row, faz m'nin tx. sütunu
        Nds[ty][tx] = Nd[(m * TILE_WIDTH + ty) * width + Col];   // N: faz m'nin ty. satırı, sütun Col
        __syncthreads();
        for (int k = 0; k < TILE_WIDTH; ++k)
            Pvalue += Mds[ty][k] * Nds[k][tx];
        __syncthreads();
    }
    Pd[Row * width + Col] = Pvalue;
}

Soru tipi 3: __syncthreads()

  • Blok içi bariyer: çağıran her thread, bloktaki tüm thread'ler o noktaya gelene kadar bekler. Farklı bloklar arasında senkronizasyon sağlamaz (bloklar arası: kernel'i bölmek / CUDA 9+ cooperative groups).
  • Bloktaki tüm thread'ler tarafından çalıştırılmalı. if/else içinde kullanmak tanımsız davranış (deadlock/yanlış sonuç); tek istisna koşulun bloktaki tüm thread'ler için aynı sonucu vermesi.
  • Hafiftir; aynı bloğun thread'leri aynı SM'ye birlikte atandığı için bekleme süreleri kısa kalır.
  • Slayt notu: aslında thread'leri değil warp'ları senkronize eder.
  • Tiled matmul'deki iki bariyer: 1. yazmalardan sonra: kimse karo dolmadan okumasın (read-after-write). 2. hesaptan sonra: kimse diğerleri bitirmeden bir sonraki fazın verisini üzerine yazmasın (write-after-read).
if (threadIdx.x < 16) {
    s[threadIdx.x] = in[threadIdx.x];
    __syncthreads();   // tid ≥ 16 buraya hiç gelmez
}
out[threadIdx.x] = s[threadIdx.x % 16];

if (threadIdx.x < 16)
    s[threadIdx.x] = in[threadIdx.x];
__syncthreads();
out[threadIdx.x] = s[threadIdx.x % 16];

Erken return da aynı tuzaktır: if (row >= n) return; yazıp sonra __syncthreads() çağırırsanız bazı thread'ler bariyere hiç ulaşmaz. Sınır kontrolünü yükleme/yazma satırlarına koyun (dışarıdakiler shared'a 0 yazsın), bariyerleri herkes çalıştırsın.

Soru tipi 4: Coalescing

  • Global bellek 32, 64 veya 128 baytlık transaction'larla okunur; sadece boyutuna hizalı segmentler okunabilir. "11 bayt okumak" yoktur, 32 bayt okursunuz; 33 bayt = iki 32 B erişim.
  • Bir warp bir global bellek komutu çalıştırınca 32 thread'in erişimleri bir veya daha fazla transaction'da birleştirilir (coalesce). Kaç transaction gerekeceğini (1) thread başına kelime boyu ve (2) adreslerin thread'lere dağılımı belirler.
  • Slayt 47 hesabı: 32 thread rastgele adreslerden 4 B okursa 32 × 32 B = 1024 B taşınır; ardışık ve 128 B hizalı okursa 32 × 4 = 128 B, tek transaction. 1024/128 = 8 kat fazla veri → bant genişliği /8.
  • Kelime boyu 1, 2, 4, 8 veya 16 B ve doğal hizalı (adres boyutun katı) olmalı; değilse birden fazla komuta bölünür. Struct'lar için __align__(8), __align__(16).
  • 2D kural: thread (tx, ty) BaseAddress + width·ty + tx'e erişiyorsa tam coalescing için hem blok genişliği hem dizi genişliği 32'nin katı olmalı → cudaMallocPitch ile satırları doldurun (padding).
  • Ardışık thread'ler (threadIdx.x) ardışık adreslere gitmeli: A[row*width + col] ✓, A[col*width + row] ✗.

Naive transpose'un neden yavaş olduğu ve shared memory ile nasıl düzeltildiği: Coalescing sayfası. Özet:

// in: height×width, out: width×height
int x = blockIdx.x * TILE + threadIdx.x;  // sütun
int y = blockIdx.y * TILE + threadIdx.y;  // satır
if (x < width && y < height)
    out[x * height + y] = in[y * width + x];
// warp'ta x ardışık: in ardışık okunur,
// out'a 'height' aralıkla yazılır

__shared__ float tile[TILE][TILE];
int x = blockIdx.x * TILE + threadIdx.x;
int y = blockIdx.y * TILE + threadIdx.y;
tile[threadIdx.y][threadIdx.x] = in[y * width + x];
__syncthreads();
x = blockIdx.y * TILE + threadIdx.x;   // bloklar yer değiştirir
y = blockIdx.x * TILE + threadIdx.y;
out[y * height + x] = tile[threadIdx.x][threadIdx.y];

Aşağıdakilerden hangisi __syncthreads() için yanlıştır?

  1. Çağıran thread, bloktaki tüm thread'ler oraya gelene kadar bekler.
  2. Sadece bazı thread'lerin girdiği bir if içinde kullanmak tanımsız davranıştır.
  3. Bir sonraki fazda shared belleğin üzerine erken yazılmasını önlemek için de kullanılır.
  4. Grid'deki tüm blokları senkronize eder.

32 thread'lik bir warp, 128 B hizalı bir float dizisinden a[threadIdx.x + 1] okuyor. Kaç tane 128 B'lık satıra dokunulur?

  1. 2
  2. 1
  3. 32
  4. 4
Hizasız (misaligned) erişim: 128 B istenir ama 256 B taşınır (32 B segmentlerle bakarsak 5 segment = 160 B). Bu yüzden başlangıç adresinin hizası önemli.

Naive transpose out[x*height + y] = in[y*width + x] (x = threadIdx.x yönü) için hangisi doğru?

  1. Okuma da yazma da coalesced.
  2. Okuma coalesced değil, yazma coalesced.
  3. Okuma coalesced, yazma coalesced değil; shared memory karosuyla ikisi de coalesced yapılabilir.
  4. Sorun global bellekte değil, sadece bank conflict'lerde.

  1. 2048
  2. 128
  3. 64
  4. 32

Bir kernel register'ı thread başına izin verilenden fazla kullanırsa ne olur?

  1. Çalışır, fazlalık local memory'ye (global bellek) taşar, performans düşer.
  2. Derlenmez.
  3. Fazlalık shared belleğe taşar.
  4. Sonuç yanlış çıkar.

Hangisi constant bellek için en iyi erişim desenidir?

  1. Her thread farklı bir adres okur.
  2. Her thread kendi adresine yazar.
  3. Ardışık thread'ler ardışık adresleri okur.
  4. Warp'taki tüm thread'ler aynı adresi okur.

Loop unrolling için hangisi yanlıştır?

  1. Döngü kontrol komutlarını (sayaç, karşılaştırma, dallanma) azaltır.
  2. Komut düzeyi paralelliği artırabilir.
  3. Register kullanımını her zaman azaltır.
  4. CUDA'da #pragma unroll ile derleyiciye yaptırılabilir.

__global__ ile işaretli bir fonksiyon için hangisi doğru?

  1. Cihazda çalışır, sadece cihazdan çağrılır.
  2. Cihazda çalışır, host'tan çağrılır.
  3. Host'ta çalışır, host'tan çağrılır.
  4. Hem host'ta hem cihazda çalışır.

Son gece kontrol listesi

  • dim3(x, y) → x sütun, y satır; row*width + col.
  • Verilen bir <<<grid, block>>> için: toplam thread, warp/blok, kapsanan bölge, belli bir thread'in (row, col)'u, bir warp'ın hangi thread'lerden oluştuğu.
  • Tiled matmul kodunu ezbere yazabilmek; Mds[ty][tx] ve Nds[ty][tx] satırlarındaki indekslerin anlamı; iki bariyerin nedeni.
  • Kare olmayan blokta (8×32) tiled versiyonu kurabilmek.
  • Bir erişim deseni için dokunulan 32/128 B segment sayısı ve verim.
  • Naive transpose neden yavaş, shared memory ile nasıl düzelir.
  • Loop unrolling: ne kazandırır, maliyeti.
  • Bellek türleri tablosu (kapsam, ömür, hız, kim yazar): L5.
  • G80/GT200 sayısal örnekleri ve CGMA.
