Özet ve sınama

Dersin ana fikirleri

  • Kernel = döngünün gövdesi; dıştaki döngüler thread'lere dönüşür. Host: cudaMalloc → cudaMemcpy (H→D) → kernel<<<grid, block>>> → cudaMemcpy (D→H) → cudaFree.
  • Global indeks = blockIdx·blockDim + threadIdx (her eksende); row-major adres row·width + col; grid'i yukarı yuvarla, sınırı kontrol et.
  • __syncthreads(): blok içi bariyer, bloktaki herkes çalıştırmalı.
  • Bloklar SM'lere blok blok atanır; warp = 32 thread, zamanlama birimi; çok warp = gecikme gizleme.
  • Naive matmul CGMA = 1 → bant genişliği sınırlı (~%6 verim). Tiling: karoyu shared'a bir kez yükle, T kez kullan → global trafik T kat az, CGMA = T.
  • Tiled kernel'de iki bariyer: yüklemeden sonra (karo dolsun) ve hesaptan sonra (üzerine yazılmasın).

Sık yapılan hatalar

  • cudaMalloc/cudaMemcpy'ye eleman sayısını vermek: boyut her zaman bayt (n * sizeof(float)).
  • Row için x, col için y kullanmak: ardışık thread'ler bellekte uzak elemanlara gider (coalescing bozulur) ve matris transpoze hesaplanır.
  • Tiled kernel'de ikinci __syncthreads()'i unutmak: hızlı thread bir sonraki fazın karosunu diğerleri okurken yazar.
  • Kernel'den hemen sonra süre ölçmek: başlatma asenkron, önce cudaDeviceSynchronize().

Final için açık uçlu sorular

1. n elemanlı bir diziyi s ile çarpan bir kernel ve onu başlatan host kodunu yazın (blok başına 256 thread, n 256'nın katı olmayabilir).

__global__ void scale(float* a, float s, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) a[i] *= s;              // fazla thread'ler bir şey yapmaz
}
// host:
float* d;
cudaMalloc((void**)&d, n * sizeof(float));
cudaMemcpy(d, h, n * sizeof(float), cudaMemcpyHostToDevice);
scale<<<(n + 255) / 256, 256>>>(d, 2.0f, n);
cudaMemcpy(h, d, n * sizeof(float), cudaMemcpyDeviceToHost);
cudaFree(d);

2. TILE_WIDTH = T olan tiled matmul'ün CGMA oranı nedir? Gösterin.

Her fazda bir thread 2 global okuma yapar (Mds ve Nds'ye birer eleman) ve iç döngüde T çarpma + T toplama = 2T FP işlem. CGMA = 2T / 2 = T. T = 16 ile 16 kat iyileşme: G80'de 21,6 GFLOPS sınırı ~345 GFLOPS'a çıkar (tepe 367'ye yakın).

3. 16×16 tile matmul'de shared bellek kullanımını ve G80'de SM başına kaç blok sığacağını hesaplayın. Sınırlayan nedir?

Mds + Nds = 2·16·16·4 B = 2 KB/blok; 16 KB/SM → shared'a göre 8 blok. Ama 256 thread/blok ile 768/256 = 3 blok. Sınırlayan: SM başına thread sayısı (shared değil).

Kendini sına

cudaMalloc((void**)&Md, size) çağrısında neden &Md veriliyor?

  1. Md host belleğinde ayrılacağı için.
  2. Boyutu bayt cinsinden vermek için.
  3. Fonksiyon ayırdığı adresi Md değişkenine yazabilsin diye.
  4. Veriyi Md'ye kopyalamak için.

256 thread'lik bloklarla bir SM'de 3 blok varsa SM'de kaç warp vardır?

  1. 8
  2. 24
  3. 768
  4. 32

Naive matmul'ün CGMA oranı neden 1'dir?

  1. Her shared bellek erişimine bir FP işlem düşer.
  2. Her thread bir eleman okur.
  3. Her thread bir register kullanır.
  4. Her turda 2 global okuma ve 2 FP işlem (çarpma, toplama) yapılır.

Tiled kernel'deki ikinci __syncthreads() kaldırılırsa ne olabilir?

  1. Bir thread bir sonraki fazın karosunu yüklerken başka bir thread hâlâ önceki fazın değerlerini okuyor olabilir.
  2. Derleme hatası olur.
  3. Pd'ye yazma coalesced olmaz.
  4. Hiçbir şey olmaz; ikinci bariyer gereksizdir.

__constant__ değişkenler için hangisi doğru?

  1. On-chip ayrı bir bellekte tutulur, önbelleğe gerek yoktur.
  2. Kernel içinde bildirilir.
  3. Tüm grid'ler aynı versiyonu görür; global bellekte saklanır ama önbelleklenir.
  4. Kernel'ler içine yazabilir.
