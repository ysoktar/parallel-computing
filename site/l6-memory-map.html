GPU belleği: tek resim ve sınırlar

Üç soru, bir bellek haritası

Bellek türlerini tek tek ezberlemek yerine onları üç soruya göre bir yapıya oturtalım. Her bellek türü bu üç sorunun bir cevap kombinasyonudur:

  1. Fiziksel olarak nerede? Yongada (on-chip: register, shared, önbellekler) mı, yonga dışında DRAM'de (global, local, constant ve texture verisi) mi? Yonga içi hızlı ve küçük, DRAM büyük ve yavaş (yüzlerce saat çevrimi).
  2. Kim görür, ne kadar yaşar? Tek bir thread (register, local), bir blok (shared) ya da tüm grid ve host (global, constant, texture).
  3. Hızlı olması için warp'ın 32 thread'i nasıl erişmeli? Her belleğin kendi "kuralı" var; hız, bu kurala uymaya bağlı.

Bir kernel, bütün bellekler

Aşağıdaki kernel'de her değişkenin hangi bellekte durduğu yorumlarda yazıyor. Kodu okurken her satırda "bu veri nerede, kim görüyor?" diye sorun.

__constant__ float coef[4];                     // CONSTANT: tüm grid görür, sadece host yazar
__device__ float total;                         // GLOBAL: tüm grid + host

__global__ void tour(const float* in, float* out, int n, int k)
{
    __shared__ float tile[256];                 // SHARED: bloktaki 256 thread aynı diziyi görür
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // REGISTER: her thread'in kendi i'si
    float acc = 0.0f;                           // REGISTER
    float hist[64];                             // LOCAL olabilir: büyük, çalışma zamanında indeksleniyor
    for (int j = 0; j < 64; j++) hist[j] = j;

    tile[threadIdx.x] = (i < n) ? in[i] : 0.0f; // GLOBAL okuma (ardışık i → coalesced) → SHARED yazma
    __syncthreads();                            // shared'ı kullanmadan önce herkes yazmış olsun
    float left = tile[(threadIdx.x + 255) % 256];    // SHARED okuma: başka thread'in yazdığı değer
    acc = coef[0] * tile[threadIdx.x] + coef[1] * left + hist[k & 63];   // CONSTANT: herkes aynı adres → yayın
    if (i < n) out[i] = acc;                    // GLOBAL yazma (coalesced)
    if (i == 0) total = acc;                    // GLOBAL
}

Hangi veri için hangi bellek?

Bir veriyi yerleştirirken soruları bu sırayla sorun:

  1. Sadece bir thread mi kullanıyor? Küçük skalerse → register (otomatik). Büyük ya da değişken indeksli diziyse derleyici local'e koyar (yavaş): küçültmeye, sabit indekslemeye (unrolling) çalışın.
  2. Bloktaki thread'ler aynı veriyi tekrar tekrar mı kullanıyor? → shared'a bir kez yükle, __syncthreads(), sonra herkes oradan okusun (tiling). Erişimleri farklı bank'lara dağıt.
  3. Salt okunur ve warp'taki herkes aynı anda aynı değeri mi okuyor? (filtre katsayıları, sabit parametreler) → constant.
  4. Salt okunur, 2D'de yerel, kesirli koordinat ya da kenar işleme gerekiyor mu? (görüntü döndürme, ölçekleme) → texture.
  5. Hiçbiri değilse (büyük girdi/çıktı dizileri) → global; erişimleri coalesced yap, 2D'de pitch kullan.

Tiled matmul'ü bu gözle okuyun: M, N, P global'de (büyük, herkes görür; yüklemeler coalesced). Karolar Mds, Nds shared'da (bloktaki 16 thread aynı elemanı kullanır). Row, Col, Pvalue register'da (thread'e özel). Bariyer, shared'ı paylaşmanın bedeli. Aşağıdaki bölümler bu resmin her parçasını ayrıntılandırıyor.

Bellek sınırları ve etkileri

  • Register sınırı, yüksek performansla (spill olmadan) çalışabilecek thread sayısını doğrudan etkiler.
  • Shared bellek sınırı, SM'de yerleşebilecek blok sayısını doğrudan (thread sayısını dolaylı) etkiler.
  • Özet: thread başına ne kadar çok bellek gerekirse SM'de (ve tüm işlemcide) o kadar az thread yerleşebilir.

G80: 16 SM, SM başına 8K = 8192 register → toplam 128K = 131.072. Çok gibi görünür ama SM başına 768 thread'i doldurmak için thread başına sadece 8192/768 ≈ 10 register.

Register spill: derlenen kod (maks. register / thread sayısı)'ndan fazla register kullanırsa kernel yine çalışır ama fazlası local memory'ye (= global bellek, thread'e özel) taşar → performans düşer. Register sayısını görmek: --ptxas-options=-v.

Shared: G80'de SM başına 16 KB, en fazla 8 blok → maksimuma ulaşmak için blok başına ≤ 2 KB. 2 KB'tan fazla kullanılırsa SM'deki blok sayısı toplam 16 KB'ı aşmayacak kadar olur.

Matmul: 16×16 tile → Mds 16·16·4 = 1 KB + Nds 1 KB = 2 KB/blok → 8 blok sığar (zaten G80 sınırı). Ama asıl sınır SM başına 768 thread: 768 / 256 = 3 blok → shared'ın sadece 3·2 = 6 KB'ı kullanılır. Bu sınırların hepsi cihaza bağlıdır.
